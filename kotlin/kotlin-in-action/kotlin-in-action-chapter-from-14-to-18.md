# 14장. 코루틴

14장에서는 코루틴을 사용해 비동기적 계산을 수행하는 코틀린의 접근 방법을 살펴보고자 한다.

- 동시성과 병렬성
    - `동시성`은 여러 작업을 동시에 처리하는 것처럼 보이게 관리하는 것에 가까우며, 코드의 여러 부분을 돌아가면서 실행된다.
    - 이처럼 동시성은 코드를 여러 부분을 나눠서 동시에 실행할 수 있다. (하나의 CPU에서 여러 애플리케이션을 돌아가면서 실행할 수 있다.)
    - 반면에 `병렬성`은 여러 작업을 여러 CPU 코어에서 물리적으로 동시에 실행하는 것을 말한다.

- 일시 중단 함수와 코루틴
    - 코루틴 특징 중 하나는 비동기적으로 실행되는 넌블로킹 동시성 코드를 우아하게 작성할 수 있게 해준다.
    - 스레드와 비교했을때 훨씬 더 가볍게 작동한다.
    - 이번 장에서는 코루틴을 사용할 때 기본적인 추상화인 `일시 중단`(suspending) 함수를 통해 순차적 코드처럼 동시성 코드를 작성할 수 있다.

- 스레드와 코루틴 비교
    - JVM에서 생성하는 스레드는 운영체제가 관리하는 스레드이며, 생성하고 관리하는데 비용이 많이 든다.
    - 코틀린에서는 스레드에 대한 대안으로 코루틴이라는 추상화를 도입했고 스레드 대비 몇 가지 **장점**이 있다.
        - [1] 초경량 추상화로, 일반 노트북에서도 10만개 이상의 코루틴을 쉽게 실행할 수 있으며 생성하고 관리하는 비용이 저렴하다.
        - [2] 시스템 자원을 블록시키지 않고 일시 중단할 수 있으며, 나중에 중단된 지점에서 재개할 수 있다. 이를 통해 비동기 작업을 처리할 때 블로킹 스레드보다 훨씬 효율적이다.
        - [3] 구조화된 동시성 개념을 통해 동시 작업의 구조와 계층을 확립하며 취소 및 오류 처리를 위한 메커니즘을 제공한다. 실패가 발생하거나 더이상 필요하지 않을 때 구조화된 동시성을 통해
          자식으로 시작된 다른 코루틴들도 함께 취소되도록 보장한다.
    - 내부적으로 코루틴은 하나 이상의 JVM 스레드에서 실행되며, 운영체제가 부과하는 스레드의 한계에 얽매이지 않는다. 즉, 코루틴은 스레드에 대한 경량 추상화를 의미한다.

### 일시 중단 함수 (suspending)

- 함수 앞에 `suspend` 변경자를 붙이면 해당 함수가 실행 중에 잠시 멈췄다가 나중에 다시 시작될 수 있다는 의미이다.
- 예를 들어, 네트워크 응답을 기다리는 경우 실행을 일시 중단할 수 있다.
- 핵심은 **스레드를 멈추는 것이 아니라, 현재 실행 중인 코루틴의 상태를 저장하고 스레드를 점유 해제**하는 것이다.

```kotlin
suspend fun login(credentials: Credentials): UserId
suspend fun loadUserData(userId: UserId): UserData
fun showData(data: UserData)

// 순차적인 코드처럼 보이지만, 내부적으로는 넌블로킹으로 동작한다.
suspend fun showUserInfo(credentials: Credentials) {
    val userId = login(credentials) // 여기서 일시 중단 가능
    val userData = loadUserData(userId) // 여기서도 일시 중단 가능
    showData(userData)
}
```

위 코드처럼 일시 중단이 제대로 동작하기 위해서는 login, loadUserData의 구현도 코틀린 코루틴을 고려해 작성되어야 한다.

주의해야할 점은 일시 중단 함수는 **다른 일시 중단 함수나 코루틴 빌더 블록**에서만 호출할 수 있다.

- 예를 들어, `showUserInfo`가 `login`과 `loadUserData`를 호출할 수 있는 이유는 `showUserInfo` 자체가 `suspend` 함수로 선언되어 일시 중단이 가능한 환경이기 때문

### 코루틴 빌더

`코루틴 빌더`는 **새로운 코루틴을 생성하는 함수**이다.

상황에 따라 **결과값의 필요 여부**나 **현재 스레드의 블로킹 여부**를 고려하여 적절한 빌더를 선택해야 한다.

- `runBlocking`
  - 코루틴이 완료될 때까지 현재 스레드를 점유하여 기다린다.
  - 전달된 코드 블록 내에서는 일시 중단 함수를 호출할 수 있다.

- `launch`
  - 결과값이 없는 새로운 코루틴을 시작할 때 사용한다.
  - 발사 후 망각 시나리오에 사용되며, 어떤 코드를 실행하되 그 결과값을 기다리지 않는 경우에 적합하다.
  - 결과값을 반환하지 않으므로 파일이나 DB에 쓰는 작업처럼 부수 효과를 일으키는 '시작 후 신경 쓰지 않아도 되는' 작업에 더 적합하다.

- `async`
  - 비동기적으로 계산을 수행하고 결과값이 필요한 경우에 사용한다.
  - 결과값으로 Deferred<T>를 반환하며, 나중에 await()를 호출하여 실제 결과값을 전달받는다.
  - 여러 비동기 작업을 동시에 실행하고 그 결과들을 합쳐야 할 때 유용하다.

### 디스패처

`디스패처`는 코루틴이 실행될 스레드나 스레드 풀을 결정하고 제어하는 역할을 한다.

코루틴은 본질적으로 특정 스레드에 고정되지 않으므로, 디스패처를 통해 실행 환경을 세밀하게 분산하거나 제한할 수 있다.

- `Dispatchers.Default`
  - CPU 집약적인 작업에 최적화된 공유 스레드 풀이다.
  - CPU 코어 수에 비례하는 스레드 수를 가지며, 계산량이 많은 알고리즘이나 JSON 파싱 등에 적합하다.

- `Dispatchers.Main`
  - UI 프레임워크(Android 등)의 메인 스레드에서 코루틴을 실행한다.
  - 단일 스레드로 동작하며, 주로 화면 갱신이 필요한 클라이언트 환경에서 필수적으로 사용된다.

- `Dispatchers.IO`
  - 입출력(I/O) 작업에 최적화된 스레드 풀이다.
    -네트워크 요청, 파일 읽기/쓰기, DB 작업처럼 대기 시간이 긴 작업을 위해 더 많은 스레드(최대 64개 또는 코어 수 중 큰 값)를 생성할 수 있도록 설계되었다.

- `withContext`
  - 이미 실행 중인 코루틴의 디스패처를 전환할 때 사용한다.
  - 새로운 코루틴을 생성하지 않고 문맥만 바꾸기 때문에, async/await 조합보다 가볍고 효율적으로 스레드 간 전환이 가능하다.

> 주의 사항: 동시성 제어

코루틴은 경량 스레드처럼 동작하지만, 멀티 스레드 환경에서 실행될 때는 여전히 **공유 자원에 대한 동시성 문제**가 발생할 수 있다.

- 여러 코루틴이 병렬로 동일한 데이터를 변경하는 경우, 데이터 무결성을 보장하기 위해 동기화 처리가 필요하다.
- 코루틴 환경에서는 코루틴 전용 비차단 잠금 방식인 `Mutex`을 사용하여 안전하게 상태를 관리해야 한다.

# 18장. 오류 처리와 테스트

## 배운 점

코루틴 빌더는 새로운 코루틴을 생성하므로, 호출한 쪽의 try-catch 블록으로는 내부의 예외를 잡을 수 없다.
- launch 빌더 안에서 UnsupportedOperationException 발생하면 예외가 잡히지 않는다.
- 올바르게 처리하는 방법은 따라서 호출부(바깥쪽)가 아닌, launch 내부 람다 블록에 try-catch를 구현해야 한다.

오류 전파 케이스: 구조적 동시성 내에서 예외가 어떻게 전파되는지에 따라 두 가지로 나뉜다. (Job vs SupervisorJob)
- Job (일반적인 전파): 한 자식의 실패가 전체 계층의 실패로 이어진다.
  - 자식 코루틴 실패 시 부모에게 예외를 전달하고, 부모는 다른 모든 자식을 취소시킨 뒤 자신도 종료된다. 이후 자신의 상위 계층으로 예외를 전파한다.
  - 이 방식은 왜 유용할까?
    - 여러 작업을 병렬로 수행할 때, 하나라도 실패하면 나머지 결과가 무의미해지는 원자적 작업을 수행할 때 데이터 일관성을 지키기 좋다.
- SupervisorJob (독립적인 실패): 자식의 실패가 부모나 형제 코루틴에게 영향을 주지 않는다.
  - 특정 자식에서 발생한 예외가 상위로 전파되지 않으며, 해당 코루틴만 종료된다.
